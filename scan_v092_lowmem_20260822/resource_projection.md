# v0.93 低内存泊松与自适应 Fock 资源报告

## 验收模型

- 轨道数：10
- 电子数：5
- `wc = 2.7 eV`
- `eta = 5.0e-7`
- `delE = -17.194874968839816 eV`
- 时间步长：`dt = 0.5 a.u.`
- 活跃轨道：0、5、6、7、8、9
- 质量指标：每个时间窗口中，QM 占据数变化 RMS 与模拟误差 RMS 的比值 `Q`；严格 Q 是六个活跃轨道中最小的单轨道 Q。

## 算法修改

1. 后向条件跳跃计数不再保存 `O(Nt^2)` 的完整尾概率表。程序只缓存每个时间点的奇、偶接受概率和首个二项质量，再用同奇偶递推反演条件分布。
2. 电子相位不再保存 `O(Nt * C(Norb, Nel))` 的时间-行列式表。程序只保存 1、2、4、8... 步的二进制相位幂，内存变为 `O(C(Norb, Nel) * log Nt)`。
3. `SEP_MB_DETERMINISTIC_FOCK=-1` 启用自动分流。若三个 Fock 工作向量的估计内存不超过 `SEP_MB_AUTO_FOCK_MAX_MIB`，使用确定性 Fock；否则使用低内存随机泊松。强制泊松和强制 Fock 仍分别用 0 和 1。
4. 每次运行输出最大单进程峰值 RSS，便于核数和内存规划。

## 纯泊松的 4000 a.u. 外推

历史同参数作业 645802 使用 100 万路径、64 核运行 4000 a.u.，耗时 4,249 秒。最后一个 100 a.u. 窗口的严格 Q 为 `3.81089e-4`。按蒙特卡洛标度

`Q(N) = Q(N0) * sqrt(N / N0)`

达到严格 `Q=10` 需要约

`N = 1e6 * (10 / 3.81089e-4)^2 = 6.89e14` 条路径。

对应总计算量约 `5.20e10 core-hours`。即使假设完全理想并行：

- 64 核：约 92,711 年
- 1,024 核：约 5,794 年
- 131,072 核：约 45.3 年
- 1,000,000 核：约 5.93 年

若把路径限制为十亿条，预计末窗严格 Q 只有约 `0.0121`。因此纯泊松在这个参数的 4000 a.u. 全程 `Q>10` 目标上不可行；障碍是实时相位/符号抵消，不是内存。

## 内存外推

在 `Nt=8000` 时，旧后向条件表单进程约占 `976.93 MiB`。v0.93 的奇偶计数缓存约 `0.366 MiB`，二进制电子相位表约 `0.054 MiB`。结合 25 a.u. 实测基线，10 轨道 5 电子的纯泊松 4000 a.u. 预计约 `9-12 MiB/进程`：

- 64 核总内存约 `0.6-0.8 GiB`
- 1,024 核总内存约 `9-12 GiB`

自动 Fock 的 256 MiB 默认工作集上限对应约 14,563 个电子行列式。10 轨道 5 电子只有 252 个行列式，因此自动选择 Fock；更大的组合空间超过阈值后自动回退到低内存泊松。

## 结论

当前 10 轨道 5 电子、4000 a.u. 的工程可行配置是：1 核、约 71 秒、约 13.77 MiB，自动选择确定性 Fock，严格 Q 最低 57.16。纯泊松分支已恢复低内存优势并保持原统计量，但不能靠十亿以内路径克服 4000 a.u. 的相位问题。
