# 30/15、4000 a.u. 抽样方式与提议速率筛选

原任务数组 647806 在所有子任务尚未执行时已取消，耗时为零，旧清单 jobs.tsv 保留以便审计。替换数组是 647807，清单 sampling_jobs.tsv，提交记录为 submit_sampling_comparison_4000.sh。每个任务 100000 路径、128 进程、每节点 64 进程，最多两小时、每节点 4 GiB；最多同时一个子任务。

| 子任务 | 前向按步固定中点分层 | 提议速率倍数 | 种子 |
| --- | --- | --- | --- |
| 0、1 | 开启 | 1.5 | 1159001、1159002 |
| 2、3 | 关闭，改用已有随机平移的总跳数 CDF 分层 | 1.0 | 1159001、1159002 |
| 4、5 | 关闭，改用已有随机平移的总跳数 CDF 分层 | 1.5 | 1159001、1159002 |

使用已有 v1.14 程序，固定同一哈密顿量并复用 647702 的 D3/F384 参考，不改变 eta、wc。缓存 key 不含提议速率，但必须通过完整模型、参考空间、时间步、进程数及校验和检查。新模式已经在现有二进制中，未上传或部署候选 C++ 源码。

替换原因：固定中点格点让每步事件数通常为 floor(N*p+0.5)，格点恰好等于 p 时按程序的严格小于条件计数，实际边缘概率变为该数除以 N。50/25、1000 路径、速率 1.5 时，事件概率相对舍入误差为 −31.74%；10000 路径时为 +2.39%。这是事件概率误差，不是占据数的百分比误差；混合控制也可能抵消部分偏差。finite_strata_probability_audit.json 保存算式与数值。关闭按步分层可避开这一处固定事件数舍入，但不能据此断言整个算法无偏，仍需检查其他条件分层及有限 dt。

资源测量在 MPI 内部用 GNU time 包住各个实际求解器进程。process-0.txt 至 process-127.txt 记录用户 CPU 秒、系统 CPU 秒、墙钟秒及峰值 KiB；process-resources.txt 汇总。分析脚本逐项重算并核对汇总。峰值和不是同时总 RSS；实测 CPU 小时区别于分配进程小时。

服务器输出路径：原 nonadia 项目下 cloud-runs/sampling-comparison-4000-20260907/647807_0 至 647807_5。运行 python analyze_sampling_4000.py 生成完整性/物理参数/缓存检查结果、相对参考诊断和图。尚未下载完整结果的任务不进入比较。

当前子任务 0、1 完成，墙钟约 36.97、36.91 分钟，实际 CPU 总计约 78.73、78.60 小时，最大进程峰值约 21.16、22.82 MiB；两次最弱轨道窗口的相对参考诊断分别 0.162、0.0257，显示偶发大权重对不同种子有显著影响。新模式尚待收齐，当前不能宣称改进成功。

参考不是完整 QM 真值，两种子不足以给出可靠置信界。不能根据单个幸运种子或早期几乎零残差形成的巨大比值宣称高精度，候选还须独立大样本验证。
